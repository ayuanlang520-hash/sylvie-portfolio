## 内容入口

| 位置 | 内容 |
| --- | --- |
| `src/_data/profile.json` | 网站标题、个人介绍、联系方式和页脚 |
| `src/_data/sections.json` | 首页板块显示、导航和新增文字板块 |
| `src/_data/projectIntro.json` | 作品区介绍 |
| `src/content/projects/*.md` | 各作品的卡片、图片、链接与详情文字 |
| `src/content/story.md` | 个人故事，支持 Markdown 强调等格式 |
| `src/_data/journey.json` | 路径区标题和时间线 |
| `src/_data/explorations.json` | 探索方向 |
| `src/_data/cooperation.json` | 合作意愿 |
| `src/_data/beichen.json` | 北辰经历区介绍和复盘入口 |
| `src/content/beichen/*.md` | 三个案例、复盘草稿和 Skill 原文页 |
| `assets/beichen/` | PDF、Skill 原文件与历史截图的展示副本 |
| `.pages.yml` | 在线后台中文字段配置 |
| `src/content/portfolio/` | 后台新增的作品 |
| `src/content/experiences/` | 后台新增的经历及关联作品 |
| `src/content/notes/` | 后台新增的复盘和实践文章 |
| `history/versions/` | 只读历史版本记录，引用对应 Git 内容快照 |

作品文件开头的结构化内容是表单数据，正文是 Markdown。Pages CMS 将这些内容映射为编辑表单。作品 `id` 用于保持原有锚点，`order` 决定排序。

## 开发与生成

使用 Node.js 22 或更高版本。在此仓库目录运行：

```powershell
npm ci
npm run build
npm start
```

开发预览地址为 `http://localhost:8091/`。`npm run build` 先清理旧 `_site/` 再生成，避免已删除内容留下残页；开发服务器也使用生成后的页面。CSS、脚本和 `assets/` 直接复制到输出目录，保留原有文件名和相对路径。

正式发布源是当前 `publish-ready` 独立仓库。上级目录的 `site/` 和 `preview-v1.2/` 保留作参考，本次没有修改。后续内容更改应发生在 `src/`；根目录的迁移前快照不再作为新内容的编辑入口。

## 验证

```powershell
npm test
```

测试先构建，然后核对：

- 本地链接和导航目标有效，允许本人正常修改文案；
- 本地资源、锚点和无障碍关联；
- 样式、交互脚本及全部媒体文件的字节一致性；
- 在隔离副本中修改数据和 Markdown 后确实生成新内容，并正确处理中文和特殊字符；
- 非法链接会使构建失败，且隔离测试不改动当前预览。
- 新页面、跨页链接、中文文件名和 GitHub Pages 仓库前缀兼容；
- 三个案例的双入口、录制缺失和复盘草稿状态明确呈现。

测试副本使用项目内的临时目录，结束后删除。`_site/`、`node_modules/` 和 `.verification/` 不进入版本控制。检查允许正常编辑内容，不使用旧页面的全文作为固定答案。

## 阶段边界

本人已要求改为保存后自动发布，并提供历史回退；本阶段实施并验收这一发布流程。

## 登录后台

打开 https://app.pagescms.org/ ，用拥有该仓库的 GitHub 账号登录。首次安装 GitHub App 时，仅选择 `sylvie-portfolio` 仓库，再进入 `main` 分支。

“北辰学习经历”下可修改三个案例和结营复盘；“已有作品”可修改原有项目。阅迹、喵学园和 Prompt Forest 在“展开详情 → 分点内容”中逐组填写“小标题”和“正文内容”，网页自动将小标题加粗并保留分栏；灵感星球的分点内容位于“项目复盘”中。个人故事和长文仍使用富文本编辑器，图片和 PDF 在“图片与附件”中上传。“新增作品”“新增经历”“复盘与实践文章”分别支持添加新内容。

保存会写入 GitHub 源文件，自动检查、构建并更新公开页面；需要等待任务完成。检查不通过会停止部署，公开网站保留上一次成功版本。每次成功发布后会自动保存一条历史记录。仓库公开，因此已保存的源文件可被他人访问，不应放入私密信息。

后台编辑不自动回写这台电脑的本地预览。下次本地修改前，先同步 `main` 分支，避免覆盖在后台保存的内容。

当前固定网址名称与标题分开保存。修改标题不会更改访问地址；新增内容的固定网址名称创建后请勿修改。

## 板块、检查与备份

“首页板块与导航”控制已有区域是否显示、是否加入导航。新增一项，选择“自定义文字板块”，填写不重复的网址名称、标题和正文，即可增加文字区域。删除或隐藏板块时，生成页面中的导航也会移除。已有区域的标题和内容仍在各自表单中修改。保存后等待自动发布完成，即可在公开网站查看。

后台操作菜单提供四个按钮：

- **检查并生成预览（不发布）**：运行内容检查，在 GitHub Actions 的本次运行中下载 `site-preview`。这是静态文件包，不是在线即时预览；请通过本地静态服务器查看。
- **重新发布当前内容**：手动重新运行检查和发布，日常保存已会自动启动。
- **创建备份**：保存 Git 版本标签，添加到后台历史列表，并在本次运行的 Artifacts 提供 `portfolio-backup` 下载，保留 90 天；Git 版本记录继续保留。
- **按备份编号恢复（高级）**：留空恢复最新独立备份，也可填写完整备份标签或 40 位提交编号。恢复完成后自动检查并重新发布。

日常回退请打开 **历史版本与回退**，按时间选择一条记录，再点击 **恢复这个版本并发布**。恢复前会自动留下当前内容的安全版本，也可在同一列表找到并恢复。文字、作品、板块和素材回到所选版本，当前程序和发布设置保留。

列表包含“发布成功”“手动备份”“恢复前安全版本”和“启用前内容备份”。只有“发布成功”表示该版本确实完成过发布；并发保存合并为一次部署时，只记录成功部署的那个版本。历史记录本身的提交不会再次发布网站。

恢复前结束其他编辑，恢复后刷新后台再继续，以免旧表单覆盖恢复结果。恢复会自动发布，请在点击恢复前核对版本。后台菜单由 Pages CMS 提供；若出现 `Failed to fetch`，重新载入后确认内容再保存。

Pages CMS 的部分控件仍是英文：`Save` 是保存、`Upload` 是上传、`Select` 是选择已有素材，`Editor / Source` 切换富文本和 Markdown 源文。新增作品等列表右上角的图标进入新建表单；已保存条目右上角更多菜单中的 `Delete` 删除条目。新建内容只需填写“固定网址名称”，文件名自动生成。

选择图片时可直接点击图片卡片，看到勾选后再点击弹窗底部的 `Select` 确认。
