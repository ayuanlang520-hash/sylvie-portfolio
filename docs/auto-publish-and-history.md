# 保存后自动发布与历史回退

本阶段依据：本人要求后台保存后自动发布，并可在误改后回到历史版本。沿用现有 GitHub Pages、Eleventy 和 Pages CMS，不新增付费服务。

## 日常流程

1. 后台保存文字、作品或素材到 main。
2. 自动检查并构建；失败时停止，公开网站保留上一次成功版本。
3. 成功部署后增加一条“历史版本”记录，包含时间、说明和对应内容版本。
4. 打开历史记录，点击“恢复这个版本并发布”。恢复前自动留下当前内容的安全版本，再恢复文字与素材，并自动重新发布。

历史版本从本次启用开始记录。先保存当前内容为“启用前内容备份”，不把它标成已经发布的新站版本。旧 Git 备份标签继续保留。

## 实现边界

- 版本列表使用仓库 `history/versions/*.json`，在 CMS 只读展示；无需输入提交编号。
- 版本快照引用 Git 的完整提交编号，内容文件由 Git 保留；记录本身不保存密码或令牌。
- 内容回退保留当前模板、发布流程和 `*.11tydata.*` 生成规则。
- 版本记录的自动提交不再次触发网站发布，避免循环。
- 恢复由 GitHub Actions 提交内容后，明确触发一次发布；不依赖机器人推送再次触发。
- 手动检查、重新发布、独立备份仍可使用。独立备份和恢复前安全版本也进入历史列表。
- 后台保存不是实时预览；更新公开网站需要等待检查和部署完成，本地预览仍独立。
